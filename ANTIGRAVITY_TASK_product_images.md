# Task: source real product photos for Vivo & Realme products

## Context
Laravel 13 e-commerce project at this repo root (`phone-shop`). Products table has a `thumbnail` column (nullable string, a public path like `/images/products/iphone-15-pro.webp`). The catalog is generated by `database/factories/ProductFactory.php`, which has a `CATALOG` constant mapping model name => `[brand name, thumbnail path or null]`.

8 of the models already have a real, legally-sourced photo in `public/images/products/` (Apple, Samsung, Xiaomi, Oppo — all from Wikimedia Commons under CC BY-SA / CC0, see `public/images/products/CREDITS.md` for the pattern to follow). These are done — do not touch them.

Two brands still have `null` thumbnails and fall back to a striped placeholder block in `resources/views/components/product-card.blade.php`:
- **Vivo**: `Vivo V29`, `Vivo Y36`
- **Realme**: `Realme 11 Pro`, `Realme C55`

No free-license real photo could be found for these 4 on Wikimedia Commons after multiple searches (checked Commons search API + Wikipedia infobox images — coverage for these budget Vivo/Realme models is essentially nonexistent under free licenses).

## Your task
Find a legally usable real product photo for as many of these 4 models as possible (swapping to a different-but-real Vivo/Realme model if a specific one has no coverage is fine, as long as you update the model name consistently in `CATALOG`, the product name pool, and the image filename).

### Hard constraints (do not skip)
1. **Only free-license images**: CC0, Public Domain, CC BY, or CC BY-SA. Acceptable sources: Wikimedia Commons, Pexels, Unsplash, Pixabay (verify the exact license on the file page, not just the site's general reputation).
2. **Never use official manufacturer/press photos** (vivo.com, realme.com, phone review sites' promotional shots, tam300.com, GSMArena, etc.) — those are copyrighted and not licensed for reuse. This app will be deployed publicly, so this is a hard legal requirement, not a style preference.
3. If a CC BY / CC BY-SA image is used, add a row to `public/images/products/CREDITS.md` (same table format already in that file: file name, source link, author, license).
4. If genuinely no acceptable photo exists for a model after a real search effort, leave its `thumbnail` as `null` — do not fabricate a photo, do not hotlink an unlicensed image, do not use an AI-generated image that closely mimics a specific real branded phone's design (trademark/trade-dress risk). The striped placeholder is an acceptable final answer for that model.

### Processing spec (match the existing images' treatment)
- Resize so the longest side is ≤ 1000px.
- Re-encode as **WebP**, quality ~78–80.
- Save to `public/images/products/{descriptive-slug}.webp` (e.g. `vivo-x100.webp`).
- Keep file size small — the existing 8 images range 6–52 KB each; stay in that ballpark.

### Wiring it into the app
1. Update the `CATALOG` array in `database/factories/ProductFactory.php`: set the thumbnail path for whichever models you found photos for (and adjust the model name if you swapped to a different real Vivo/Realme model than what's currently listed).
2. Run `php artisan migrate:fresh --seed` to reseed the database with the new thumbnails.
3. Rebuild frontend assets if needed: `npm run build`.
4. Verify visually: start `php artisan serve`, open the storefront home page and `/san-pham` (products listing), confirm the Vivo/Realme cards show the new photos (or the placeholder if none found) and nothing looks broken.

## Report back
When done, summarize: which models got real photos (with source/license), which stayed on placeholder and why, and confirm the reseed + visual check passed.
